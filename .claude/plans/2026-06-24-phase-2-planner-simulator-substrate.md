# Plan: Build-out Phase 2 — the planner simulator + strategy substrate

**Goal:** Make the offline loop a *real* optimizer: a candidate carries a structured **strategy genome** that a deterministic **planner simulator** interprets into different plans → events → metrics → North Star, scored by the existing harness, with a **heuristic search proposer** that perturbs a **champion** genome — so a candidate's content (not a hand-set `improve` flag) drives whether it wins.

**Out of scope (deferred, gated behind this):** the real Claude-Agent-SDK proposer (needs API credentials — STOP-and-surface if reached; it plugs into the *same* `Proposer` interface + genome type built here); the production funnel / experiment engine; `agent-operations/`; the *production* trusted-evidence channel. This phase is **fully offline, deterministic, zero side effects** — same rails as Phase 1.

## Operating philosophy (read first)

Same as Phase 1 ([[agents-own-buildout-decisions]]): the building agent owns the engineering decisions; the non-negotiables are the safety rails (offline-first, reuse the ONE safety model, ground every artifact in the specs, optimize toward the North Star), not the *how*. Amend this plan as reality diverges (`executing-plans`).

## Context

The offline loop is real end-to-end **except** the `ProductRunner` — the fitness function's signal generator. Today `ProductRunner = (scenario, variant) => ScenarioExecution` is **candidate-blind** (`eval-harness/src/scoring/offline_scorer.ts:52`); the Phase-1 stub toggles a hand-set `improve` boolean (`loop-orchestrator/tests/fixtures/rsvp_corpus.ts:24,61`) and the loop test fakes improvement with a `callCount` closure (`loop-orchestrator/tests/loop/offline_loop.test.ts:53`). So the loop currently optimizes nothing real.

Two specialist reviews (rigorous-architect, testineer) shaped this plan. The load-bearing decisions:

1. **Keep the genome OUT of the `candidate_change` contract** (a firewall artifact) — but **content-address** it so the candidate cryptographically commits to exactly the genome that runs: `artifact_ref = "genome:<sha256(canonicalJson(genome))>"`. The simulator recomputes the hash and **refuses on mismatch**. This closes the "reviewed candidate, unreviewed genome" seam. Reuse the existing `canonicalJson` + `sha256Hex` (`shared/src/index.ts`) — do not invent a parallel mechanism ([[loop-trusted-evidence-boundary]]).
2. **Split the simulator into two stages with a real boundary** so the INTEGRITY gate stays load-bearing (a single-author simulator makes `INTEGRITY.SELF_REPORT_DIVERGENCE` vacuous): **Stage A — planner** consumes `(scenario, genome)` and emits *only* `productEvents` (claims); **Stage B — harness** writes the `TrustedRecorder` independently from the scenario's **persona ground truth** (`scenario.couple`/`guests`/`bookedPlanFacts`), never from Stage A's output. This honors the DEFERRED FEED-PATH INVARIANT in `eval-harness/src/trusted_recorder/trusted_recorder.ts` ([[prod-trusted-evidence-channel]]).
3. **Champion is NEW construction** (no champion concept exists anywhere yet): an explicit, injected, human-seeded `ChampionStore`; promote-on-offline-accept (a documented offline-only simplification — offline has no `promoted` transition); champion lineage recorded as *evidence in* the ledger (free-form `evidence_ref`/`grade_report_refs`), never as new mutable state. The champion ratchets monotonically → real hill-climbing.
4. **Lessons dedupe on the genome hash**, not `candidate_id` (else the proposer re-proposes the same losing genome under fresh ids forever). The content-address hash is both the firewall binding AND the lessons key.
5. **The oracle must be non-circular** (the simulator produces the very events the metrics read): tests assert *metamorphic relations* (monotone genome→metric directions; anti-Goodhart guard tradeoffs), *boundary fixed-points*, and *property invariants* — never a hand-computed interior value. Plus an **anti-no-op test**: `∀ genome param ∃ scenario: flipping only that param changes the event stream` (the dual of the determinism test; the one tripwire for a candidate-blind simulator masquerading as "search dry").

First parameter (the smallest proving slice): **`rsvp_reminder_cadence`** → moves `rsvp_resolution_rate` (already implemented; events `guest.rsvp.{requested,reminded,received}` exist), guarded by `guest_sentiment_score` (already implemented; event `guest.sentiment.sampled` exists) so nagging trades off — exercising the accept rule's guard condition against the new substrate. Tier 0/1 (no spend/comms/autonomy surface).

Grounding files: `loop-orchestrator/proposer_design.md`, `loop-orchestrator/risk_tier_derivation.md` (doc-only, unbuilt), `loop-orchestrator/safety_and_governance.md` §1/§7, `telemetry/metric_catalog.md`, `loop-orchestrator/src/pipeline/deterministic_selector.ts` (the surprise check / `hypothesis_confirmed`).

## Steps

- [ ] **Step 1: The `strategy_genome` contract + content-address + fingerprint (in `shared`).**
  - Add `shared/schemas/strategy_genome_schema.json` (draft-2020-12, `additionalProperties: false`), register it in the schema registry + `gen:types` like the other 12 contracts. v1 fields: `genome_id`, `parameters` (a closed object; ship `rsvp_reminder_cadence: integer 0..3` first), plus room to grow. Implement `canonicalGenomeHash(genome): string` = `sha256Hex(canonicalJson(genome.parameters))` (hash the *parameters*, not the id, so two genomes are equal iff behavior-equal) and `genomeArtifactRef(genome) = "genome:" + hash`.
  - Verify: `npm run build && npm test` — a test asserts (a) the schema compiles + a sample genome validates via `assertValid`, (b) hash determinism (same params → same hash; param change → different hash), (c) `genome_id` does NOT affect the hash (fingerprint = behavior, not identity).
  - Specialist: `doddy` *(content-addressing is the firewall binding for "the thing that actually runs" — verify the hash can't be spoofed/aliased and that hashing `parameters` only is the right boundary).*

- [ ] **Step 2: The genome→surface map + `deriveRiskTier(genome)` (the firewall's first real mechanism).**
  - A **trusted, human-maintained** map from genome parameter → sensitivity surface → risk tier (the genome analogue of `risk_tier_derivation.md`'s path→surface map; lives outside any proposer's write scope). `deriveRiskTier(genome) = max over touched params`. v1 entries: `rsvp_reminder_cadence → tier 0`; reserve `autonomy_*`/`auto_commit_* → tier 2`, any spend-model param → tier 3 (prohibited). A param absent from the map → reject (fail closed, legible).
  - Verify: `npm test` — tests assert (a) a known param maps to its tier, (b) an unmapped param fails closed, (c) `deriveRiskTier` returns the max across params. (Reconciliation against the candidate's *declared* `risk_tier` is wired in Step 6.)
  - Specialist: `doddy` *(this is the under-declaration / firewall-evasion check; verify fail-closed and that the proposer cannot reach the map).*

- [ ] **Step 3: The planner simulator — Stage A (planner→claims) / Stage B (harness→trusted record), in `eval-harness`.**
  - `makePlannerSimulator({ championGenome, candidateGenome, registry, clock, ids }) => ProductRunner` — the `ProductRunner` signature stays `(scenario, variant)` (candidate-blind at the scorer boundary; genomes bound at factory construction). Variant `baseline` → champion genome; `candidate` → candidate genome. **Stage A** interprets `(scenario, genome)` → emits `productEvents` only (for `rsvp_reminder_cadence`: emit `guest.rsvp.requested` per guest, then up to `cadence` `guest.rsvp.reminded`, then `guest.rsvp.received` for guests modeled to respond, plus `guest.sentiment.sampled` whose score *decays* as cadence exceeds a comfort threshold). **Stage B** writes the `TrustedRecorder` from the persona ground truth only. The factory **verifies** each genome's content-address against its `artifact_ref` and throws on mismatch. Per-scenario id/`wedding_id` namespacing preserved (no cross-scenario collision).
  - Verify: `npm test` — (a) byte-identical replay (two fresh equal clocks/ids → `JSON.stringify` equal), (b) cross-scenario `event_id` sets disjoint, (c) Stage B's trusted record derives from persona, not Stage A (a test where Stage A "lies" — emits an event contradicting the persona — and `INTEGRITY.SELF_REPORT_DIVERGENCE` *fires*, proving the gate is non-vacuous), (d) no ambient `Date.now`/`Math.random` (static grep + runtime stub-throws).
  - Specialist: `testineer` *(the oracle/integrity-vacuity risk lives here — verify the Stage-A/B boundary and the non-circular test set).*

- [ ] **Step 4: Metamorphic + anti-no-op tests for the simulator (the non-circular oracle).**
  - Encode the directional oracles over the *real* simulator + *real* metric engine: (a) **monotone** — raising `rsvp_reminder_cadence` within band must NOT decrease `rsvp_resolution_rate`; (b) **anti-Goodhart guard tradeoff** — pushing cadence past the comfort threshold must NOT raise `guest_sentiment_score` (it should fall); (c) **boundary fixed-point** — all-already-resolved scenario → rate `1.0` regardless of genome; zero-requested → rate `null` (not `0`); (d) **anti-no-op** — for `rsvp_reminder_cadence` there exists a scenario where flipping only it changes the event stream AND moves the metric in the correct sign.
  - Verify: `npm test` — all of the above pass; **no test asserts a hand-counted interior event total** (each assertion is a relation between two runs, a domain fixed-point, or an invariant).
  - Notes: this is the keystone *unit*-level guard against the "simulator models nothing real" / "candidate-blind" failure that passes every other test.

- [ ] **Step 5: The `ChampionStore` + genome registry wiring (in `loop-orchestrator`).**
  - An injected `ChampionStore` seeded with a champion genome (the "current product"); `current()` returns it, `promote(genome)` advances it. An injected content-addressed genome registry (`genomeHash → genome`, a plain Map passed in — no stateful singleton) the proposer writes and the simulator resolves. Document the offline-only simplification (promote on offline-accept; offline has no `promoted` transition).
  - Verify: `npm test` — tests assert seed→current, promote advances current, registry resolves a registered genome and rejects an unregistered/hash-mismatched ref.

- [ ] **Step 6: The `SearchProposer` (implements `Proposer`, in `loop-orchestrator`).**
  - Perturbs `championStore.current()` toward `weakestCapability`: **exploit** (bounded single-param perturbation) majority, **explore** (occasional larger/structural move) minority, deterministic from `(champion, lessons, iteration)` via injected ids (no `Math.random`). Emits a schema-valid `CandidateChange` with `artifact_ref = genomeArtifactRef(genome)`, `risk_tier = deriveRiskTier(genome)` (the *declared* tier now equals the derived tier — Step 2's reconciliation closes the under-declaration path here), registers the genome, and **never re-proposes a genome whose hash is in `lessons`** (dedupe on hash). Returns `null` when its neighborhood for the current target is exhausted.
  - Verify: `npm test` — property tests: (a) never returns a genome whose hash is in seeded rejected-lessons, (b) exploit output within bounded param-distance of champion, (c) determinism (same inputs → same proposal), (d) terminates (`null` / loop goes dry over a finite space), (e) coverage grows over a deterministic proposal sequence.
  - Specialist: `wolf` *(exploit/explore balance + convergence-without-pinning — verify the search properties are sound, not brittle exact-output pins).*

- [ ] **Step 7: Wire the loop end-to-end + the keystone integration test.**
  - Replace the Phase-1 stub scorer/runner wiring: the loop builds the runner via `makePlannerSimulator` with `{ championGenome: store.current(), candidateGenome }` each iteration, scores through the **unmodified** `scoreCandidateOffline` + `runOfflineSelection`, and on accept calls `store.promote(candidateGenome)` and writes the genome hash into the accepting transition's `evidence_ref`/`grade_report_refs`. Update `loop-orchestrator/tests/fixtures/rsvp_corpus.ts` consumers; keep the old hand-scripted fixture only if still used as a pure unit double, else retire it.
  - Verify: `npm run build && npm test && npm run lint` — the **keystone** test, two arms: **positive** — a challenger genome (higher cadence, within band) genuinely beats the champion: `rsvp_resolution_rate(candidate) > baseline` (real metric engine over simulator events), `hypothesis_confirmed === true` with high `target_attribution_share` (`deterministic_selector.ts`), guard `guest_sentiment_score` held, accept rule `accepted`, ledger reaches `offline_passed`, chain verifies, champion advanced; **negative** — a challenger that pushes cadence past the comfort threshold raises `rsvp_resolution_rate` but tanks `guest_sentiment_score` → accept rule **rejects** (guard regression), a lesson is written, champion unchanged. No `improve`/`callCount` cheat anywhere.
  - Specialist: `testineer` *(verify the keystone asserts the causal chain — genome delta → metric moved → hypothesis_confirmed → guard held → accept — not just that the plumbing runs).*
